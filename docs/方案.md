# 观澜 NetScope · 用户上网行为管理与态势感知系统 — 设计方案

> 目标设备：OpenWrt 旁路由 `192.168.1.254`（Phicomm N1 / aarch64 / OpenWrt SNAPSHOT R2024.11.05 flippy-92+o）
> 产品代号：**观澜 NetScope**（内部模块名 `guanlan`）· 访问地址：`http://192.168.1.254:8088`

---

## 1. 环境探测结论（实测）

| 项目 | 探测结果 | 对方案的影响 |
|---|---|---|
| 硬件 | Phicomm N1，ARMv8 4 核，1844 MB 内存（可用 ≈1.3 GB），eMMC 960 MB（overlay 余 ≈210 MB）+ `/mnt/mmcblk2p4` ext4 4.2 GB 可用 | 资源足够跑常驻服务；程序与数据分离，数据落 `mmcblk2p4` |
| 系统 | OpenWrt SNAPSHOT，内核 6.1.114-flippy-92+o，busybox，opkg，1301 个包，175 个 LuCI 应用 | 生态齐全，可用现成内核模块 |
| 网络角色 | 旁路由：`br-lan 192.168.1.254/24`，默认网关 `192.168.1.1`；本机 DHCP 下发网关 192.168.1.254 | **LAN 终端流量实际经过本机**，可做全量行为观测 |
| 连接跟踪 | `nf_conntrack_count≈1.46 万 / max 32.7 万`，`nf_conntrack_acct=1`（含每流字节/包数） | 实时流量、会话、应用归因的核心数据源 |
| iptables | iptables-legacy 1.8.7 + 全套 match/target（`libxt_ACCOUNT`、ipset、geoip、account 等），282 条规则，passwall 占用 mangle | 可实现封禁、分流、限速；注意与 passwall/docker 规则共存 |

| 服务 | uhttpd :80/:443（LuCI）、ttyd :7681、netdata :19999、dnsmasq :53、dnscache :5333、docker 27.2（无容器，data-root 在 mmcblk2p4） | 8088 端口空闲；Docker 可选但本方案采用原生部署更省资源 |
| DNS | dnsmasq 2.88 → 上游 `127.0.0.1:5333`(dnscache)；`conf-dir=/tmp/dnsmasq.d` 可挂载自定义配置 | **通过 conf-dir 旁挂 `log-queries` 获取域名访问行为，可一键还原** |
| 时间/时区 | CST-8，时间准确 | 统计对齐自然日/小时 |
| 外网 | 路由器与外网均可达（ping 31 ms、opkg/npm 镜像 200） | 可拉取依赖与镜像 |

**结论**：本机具备"全流量观测 + 策略下发"的完整条件，无需旁挂镜像口；唯一需要改动路由器的地方是**只读性质的 DNS 查询日志旁挂**（可秒级还原）。

## 2. 需求与功能范围

### 2.1 目标
面向家庭/小型办公场景，提供"看得见（态势）、说得清（分析）、管得住（管控）"的一体化平台：

1. **3D 托盘态势大屏**：路由器为核、设备为星、流量为轨，一屏看清全网态势。
2. **流量分析统计**：实时速率、协议/应用/域名/设备多维聚合，1 分钟粒度留存 14 天，实时曲线 5 分钟。
3. **用户上网行为管理**：设备识别与别名、分时段断网、网站/应用分类封堵、按设备限速、黑白名单。
4. **安全态势感知**：端口扫描、异常外联、黑名单域名、DNS 隧道嫌疑、流量异常等规则检测与告警流。

### 2.2 非目标（v1 不做）
- 不做基于原始报文捕获的 DPI（无 libpcap/镜像口，成本与稳定性不划算）；
- 不做多用户权限体系（单管理员 + 会话）；
- 不替换现有 LuCI/passwall/adbyby，互不干扰、可随时卸载。

## 4. 数据采集设计

| 数据源 | 采集方式 | 频率 | 产出 |
|---|---|---|---|
| 连接跟踪 | 读 `/proc/net/nf_conntrack`，解析五元组+双向字节+状态，按 flow 做**字节差分**求增量 | 2 s | 设备实时速率、会话明细、目标 IP 流量 |
| DNS 行为 | 旁挂 `/tmp/dnsmasq.d/99-guanlan-logging.conf`（`log-queries`+`log-facility`），tail 日志 | 实时流 | 设备→域名访问、域名→IP 映射（用于把 conntrack 目标 IP 归因到域名/应用） |
| 设备发现 | `/tmp/dhcp.leases` + `ip neigh` + conntrack 源 IP | 10 s | 设备清单、主机名、MAC、在线状态 |
| 系统指标 | `/proc/stat`、`/proc/meminfo`、`/proc/net/dev`、`/proc/loadavg`、`thermal_zone` | 2 s | CPU/内存/负载/温度、WAN/LAN 吞吐 |
| 应用库 | 内置域名分类库（≈400 条规则）+ 端口启发式 | 静态 | 域名/连接→应用分类 |

### 4.1 字节差分算法
每条 flow（`orig_src,orig_dst,sport,dport,proto`）记录上次 `bytes/packets`，每 2 s 求差：
- `src` 属于 LAN → 该方向计入 **上传(up)**；
- `reply` 方向 → 计入 **下载(down)**；
- 归属设备 = LAN 源 IP；归属域名 = 目标 IP 反查 DNS 映射（带 TTL 衰减），无映射则按端口/协议归 `other`。

### 4.2 DNS 旁挂的启停（可逆，已实机验证）

> 实测结论（重要，避免踩坑）：
> - 该固件 `/etc/init.d/dnsmasq` **原生支持** UCI 选项 `dhcp.@dnsmasq[0].logqueries`（→ `--log-queries=extra`）与 `dhcp.@dnsmasq[0].logfacility`（→ `--log-facility`）。因此用 UCI 开关是**最规范、最可逆**的做法：不改固件自带的 `/etc/dnsmasq.conf`（其中含 `log-facility=/dev/null`），也不新增 conf-dir 文件。
> - 禁止在 `/tmp/dnsmasq.d/*.conf` 里写 `log-facility=...`：主配置已占用该关键字，dnsmasq 会以 `illegal repeated keyword` **启动失败**，全网 DNS 中断（已实测踩坑并恢复）。
> - `ubus call dnsmasq reload` 在该版本**不存在**（ubus 仅有 `metrics` / `set_connmark_allowlist`）；`/etc/init.d/dnsmasq reload` 存在 bug（停得掉、起不来）。**只能用 stop + start 两步**。
> - dnsmasq ubus 没有缓存导出接口（metrics 仅为计数器），故"客户端→域名"映射必须开日志才能获得。

- **启用**：`uci set logqueries=1` + `uci set logfacility=/tmp/guanlan/dnsmasq.log` + `uci commit dhcp` → stop/start dnsmasq → 健康检查（解析成功）→ 失败自动 `uci delete` 回滚并再次 stop/start。
- **停用**：`uci delete` 两个选项 + commit → stop/start → 健康检查 → 完全还原。
- **日志格式**（实测）：
  ```
  Oct 31 16:25:38 dnsmasq[26278]: query[A] tracker.torrent.eu.org from 192.168.1.106
  Oct 31 16:25:38 dnsmasq[26278]: reply tracker.torrent.eu.org is 89.234.156.205
  Oct 31 16:25:38 dnsmasq[26278]: cached tracker.parrotlinux.org is NXDOMAIN
  ```
  由此构建 `IP→域名`（TTL 30 min）与 `域名→IP`（带 TTL）双向映射，把 conntrack 的目的 IP 归因到域名与应用分类。
- **日志落 tmpfs**（`/tmp/guanlan/dnsmasq.log`），重启即失，不占 overlay；采集器按 offset 续读，文件重建时归零重读；采集失败自动降级，仅失去"域名/应用"维度。
- **域名封堵不走 dnsmasq**（避免每次改动都重启 DNS 服务）：域名 → 解析 IP → 写入 ipset `ubm_block` → iptables 自有链 `UBM_FWD` 丢弃命中流量。
- 重启 dnsmasq 期间 DNS 有约 1–2 秒空窗，属可接受范围；任一步失败必须回滚到"DNS 可解析"状态。

## 5. 功能模块

### 5.1 3D 托盘态势大屏（`#/screen`）
- **场景**：深空渐变 + 极坐标网格地面 + 倒影圆盘；
- **托盘**：中心六边形"路由核心"（脉冲光晕 + 三层旋转光环），外围同心圆托盘；
- **分类扇区**：8 类流量（视频/游戏/社交/网页/下载/邮件/云盘/其他）以环形扇柱挤出，**高度=当前占比**，360° 缓慢自转；
- **设备星位**：每台设备一枚发光芯片，分布在托盘外环，**光柱高度=实时速率、颜色=风险等级**，与核心之间由贝塞尔曲线轨道相连，粒子沿轨道流向核心；
- **刻度环**：托盘外缘 60 段细柱 = 最近 60 个采样点的上下行趋势；
- **HUD**：左上品牌+时间，右上系统 KPI（在线设备/连接数/总速率/告警数），右侧告警流，底部图例与 Top 设备条；
- 交互：拖拽旋转/滚轮缩放/自动巡航；点击设备芯片 → 弹出该设备实时详情。

### 5.2 设备管理（`#/devices`）
设备列表（IP/MAC/主机名/厂商/在线/实时速率/累计流量/风险分），支持：别名、分组标签、一键断网/恢复、限速、拉黑域名、查看该设备域名与连接明细、历史曲线。

### 5.3 流量分析（`#/traffic`）
时间范围 1h/6h/24h/7d；上下行堆叠面积图；分类占比环图；Top 设备/应用/域名 Top10；实时连接表（可搜索、可封禁目标）。

### 5.4 行为管控（`#/behavior`）
- **访问控制策略**：按设备/分组 + 生效时段（周几+时间窗）+ 动作（禁止上网/仅允许学习类/限速）；
- **分类封堵**：勾选分类（游戏、短视频、赌博等）即对目标设备生效；
- **域名黑/白名单**：写入 dnsmasq `address=/domain/0.0.0.0`，支持通配与一键恢复；
- **限速**：tc htb + ifb，按设备下行/上行限速（默认不限，失败自动回滚）。

### 5.5 安全态势（`#/security`）
规则：端口扫描（目标端口数/窗口）、高危端口外联、黑名单域名命中、DNS 隧道嫌疑（长标签/TXT 激增）、异常大流量、新设备入网、设备离线。事件带级别（info/warn/critical）、设备、证据，可确认/忽略，形成设备风险分与趋势。

### 5.6 设置（`#/settings`）
采集间隔、数据保留天数、DNS 旁挂开关、告警阈值、修改管理密码、系统信息、卸载指引。

### 5.7 开关体系（两级，默认全关）

系统**默认完全关闭**：不采集、不管控、不改动路由器任何现有配置；关闭状态下前端仍可访问，并提示"系统未启用"。

| 级别 | 开关 | 作用 | 关闭时的撤销动作 |
|---|---|---|---|
| ① 总开关 | `enabled` | 系统总开关 | 级联关闭全部子开关，并撤销全部已下发的 iptables / ipset / tc / dnsmasq 变更 |
| ② 功能开关 | `collect` 流量采集 | conntrack / DNS / DHCP 采集 | 停止采集，设备列表与图表为空 |
| | `dnsTap` DNS 行为日志 | dnsmasq 查询日志旁挂 | `uci delete` 两个选项 + commit + dnsmasq stop/start + 健康检查，失败自动回滚 |
| | `deviceControl` 设备管控 | 断网 / 限速 | 删除 UBM_FWD / UBM_IN 全部规则、清除 tc |
| | `domainBlock` 域名封堵 | ipset 封禁 | 销毁 ipset `ubm_block` + 删除拦截规则 |
| | `schedule` 定时策略 | 时间窗自动启停 | 停止调度器（已生效规则随对应开关关闭而撤销） |
| | `alerts` 安全告警 | 规则研判与事件 | 停止研判，历史事件保留可查 |
| | `history` 历史统计 | 1min 桶落盘与保留 | 停止写盘，清理当天 JSONL |

**安全不变量**：任一开关处于关闭状态时，路由器行为与"从未安装本系统"完全一致（可用 `deploy/rollback.sh` 验证等价性）。
开关变更统一走 `PUT /api/settings`，响应返回本次实际执行/撤销的动作列表，便于审计。

## 6. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Go 1.26 标准库零依赖**，`CGO_ENABLED=0` 交叉编译 aarch64 静态二进制 | 单文件、无运行时、内存占用低（≈25 MB）、10 ms 级响应 |
| 实时推送 | **SSE**（`text/event-stream`） | 比 WebSocket 更简单可靠，标准库即可，自动重连 |
| 存储 | 内存环缓冲 + 按天 JSONL（1 min 桶，uptime 落盘） | 无 SQLite 依赖，读放大可控，4 GB 分区足够存 14 天 |
| 前端 | 原生 ES Module + **Three.js**（本地内置）+ 自研 Canvas 图表 | 无构建步骤、无 CDN、离线可用，部署即生效 |
| 进程管理 | procd `/etc/init.d/guanlan` | OpenWrt 原生，开机自启、崩溃重启 |
| 构建/部署 | Windows 侧 `go build` + `scp` + `ssh` 安装脚本 | 开发机即构建机，秒级发布 |

## 7. 部署与运维

### 7.0 随时回退（用户自助，零依赖）

提供**双保险**回退手段，任何时候用户都能自己执行，无需开发者协助：

| 工具 | 位置 | 用法 | 效果 |
|---|---|---|---|
| 极速自保回退 | `deploy/rollback.sh`（路由器）/ `deploy/rollback.ps1`（Windows） | `.\deploy\rollback.ps1` 或 `sh /tmp/rollback.sh` | 把路由器恢复到"从未安装过本项目"的状态 |
| 完整卸载 | `deploy/uninstall.sh` | `sh uninstall.sh [--purge]` | 完整卸载流程，支持保留/删除数据目录 |

**回退保证（已在 mock 环境实测通过）**：
- **只做减法**：仅删除本项目创建的二进制、init 脚本、配置、数据、UBM_* 自有链、ipset、tc/ifb、DNS 旁挂 UCI 选项；
- **零误伤**：passwall 的 PSW 链、docker 的 DOCKER-USER、FORWARD/INPUT 的既有 ACCEPT 规则全部保留（mock 断言 PASS）；
- **不重启路由器**、不动 DNS 上游、不动防火墙 lan 区、不动网卡；
- dnsmasq 只做 stop+start（禁用有 bug 的 reload），每次启停后 nslookup 健康检查，失败立即再恢复；
- 脚本退出前必须保证 DNS 可解析，否则走紧急恢复分支；
- 可重复执行（幂等）。

### 7.1 部署形态

```
/usr/sbin/guanlan                 服务端二进制（go:embed 前端）
/etc/init.d/guanlan               procd 启动脚本（enable/start/stop/restart）
/mnt/mmcblk2p4/guanlan/           数据目录
  ├─ state.json                   设备/策略/设置/事件（原子写）
  ├─ traffic-YYYY-MM-DD.jsonl     1 分钟聚合流水（保留 14 天）
  └─ guanlan.log                  运行日志（5 MB × 3）
/tmp/guanlan/                     运行时日志（DNS 旁挂）
/tmp/dnsmasq.d/99-guanlan-logging.conf   DNS 旁挂配置（可删除还原）
```

- **安装**：`deploy/install.sh`（幂等）→ 生成配置与初始密码 → 启动 → 自检；
- **升级**：覆盖二进制 + `restart`，数据不动；
- **卸载**：`deploy/uninstall.sh` 停止服务、删除二进制与 init 脚本、删除 DNS 旁挂与 iptables/tc 残留规则，数据目录可选保留；
- **端口**：8088（LAN 可访问，防火墙 lan 区默认 ACCEPT）；
- **鉴权**：单管理员密码（`sha256(salt+pwd)` 存 `/etc/guanlan/config.json`），会话 Cookie 24 h，默认密码首次安装时输出并可在设置页修改。

## 8. 资源占用预算（低占用原则）

设备为 N1（1844 MB 内存，已跑 netdata / passwall / adbyby / openclash 等），overlay 仅余 209 MB，因此本系统按**最小开销**设计：

| 项目 | 预算 | 做法 |
|---|---|---|
| 服务常驻内存 | ≤ 60 MB RSS | conntrack 逐行流式解析（不整文件读入）、只对 LAN 侧且有增量的 flow 做聚合、域名/IP 反查表带 TTL + 容量上限（域名 5k、IP 20k）、flow 差分快照上限 2 万条 |
| 空闲 CPU | ≤ 3%（四核） | 采集用 time.Ticker（2s/10s）而非忙等；策略评估 15s 一次；SSE 仅在有订阅者时序列化 |
| 磁盘 | ≤ 60 MB（14 天） | 1min 桶按天 JSONL 滚动 + 按 retentionDays 删除；state.json 只存小体量状态，脏标记合并写（≤60s 一次），事件保留 500 条 |
| 3D 大屏 | 30fps 常态、JS 堆 < 150 MB | 自适应帧率（静止 12fps / 交互 60fps）、InstancedMesh 复用几何、粒子单 Points ≤200、关阴影与 Bloom、纹理 LRU 64、dispose 全释放（避免 WebGL 上下文泄漏） |
| 前端 | 无常驻轮询 | 页面只在 SSE tick 时更新受影响组件；路由切换销毁监听器/图表/Observer；长列表分页（50/页） |
| 前端资源 | 0 外部依赖 | 无 CDN、无 webfont、无图片素材，图标内联 SVG |

验收：部署前后记录 `free -m` / `df -h /` / 进程 RSS 与空闲 CPU 占用，写入 `docs/verify-report.md`。

## 9. 风险与控制

### 9.0 操作安全红线（最高优先级）

本系统运行在用户**正在使用的**家用路由器上，任何影响连通性的操作都遵循以下纪律：

| 类别 | 操作 | 规则 |
|---|---|---|
| 只读 | 采集 /proc、netstat、ip neigh、dnsmasq 日志读取、端口探测 | 随时可执行 |
| 配置写入 | 部署二进制、写 /etc/init.d、创建数据目录 | 需用户许可；先备份；幂等；失败回滚 |
| 连通性相关 | **stop/start dnsmasq**、改 iptables 链、改 tc qdisc、改防火墙/DNS 上游 | **必须用户在场许可后执行**；执行前快照现状（iptables-save、uci show dhcp）；执行后健康检查；失败立即回滚；绝不允许以"DNS/网络不可用"的状态结束 |
| 禁止 | `/etc/init.d/dnsmasq reload`（该固件有 bug，停得掉起不来）、`ubus call dnsmasq reload`（方法不存在）、修改 lan 区防火墙配置、删除非本项目文件/规则 | 任何时候禁止 |

实现层保障：所有外部命令经统一执行器串行化，命令级错误立即回滚；提供干跑模式（不执行真实命令，仅记录）；危险动作前置健康检查。

### 9.1 其他风险

| 风险 | 控制措施 |
|---|---|
| DNS 旁挂导致解析异常 | 仅追加只读日志选项；写后 `reload` 不 `restart`；异常自动删除配置回滚；开关可关 |
| 管控规则误伤上网 | 规则只作用于指定 LAN 设备；iptables 规则打 `UBM` 标记便于清理；限速默认关闭、失败回滚；提供"一键恢复全部策略" |
| 与 passwall/docker 规则冲突 | 自有链 `UBM_FWD`/`UBM_IN` 插入 FORWARD/INPUT 首部，删除时按链清理，不触碰他人规则 |
| 内存/磁盘占用 | 环缓冲上限 + 按天滚动删除 + 日志切割；实测目标常驻 < 60 MB |
| 采集中断 | 采集器 panic 恢复 + 看门狗；SSE 断线自动重连；页面降级显示"数据延迟" |
| 权限 | 服务以 root 运行（需操作 iptables/tc）；仅监听 LAN 地址 |

## 11. 验收标准

1. 浏览器打开 `http://192.168.1.254:8088`，登录后 3D 托盘大屏可交互、数据 2 s 刷新、无 WebGL 报错；
2. 设备列表与真实局域网设备一致（主机名/MAC/IP），实时速率与 `conntrack` 增量吻合；
3. 流量页 4 种时间范围均有正确曲线与 Top 榜；
4. 行为页可对任一设备断网/恢复、封堵分类、限速，操作后 `iptables-save`/`tc` 可见对应规则，且可一键还原；
5. 安全页能产生并展示真实事件（如新设备、高危端口、黑名单域名）；
6. 卸载脚本执行后路由器无残留（端口关闭、规则清理、DNS 配置还原）；
7. **资源占用达标**：服务常驻 RSS ≤ 60MB、空闲 CPU ≤ 3%、3D 大屏 1920×1080 稳定 30fps、磁盘增量 ≤ 60MB。
